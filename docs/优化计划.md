# 降低 CDN 流量与调用消耗 · 三批开发计划

> 原文于 2026-10-13 经 plan 模式批准（green-lantern-batman-orion v4），从会话存档恢复并存档于此。
> 状态标注为执行过程中的最新事实。

## 现状诊断（计划制定时）

**调用侧**（全部经 `services/api.ts` 的 `call`）：
- `pages/roof/index.ts` `onShow` 固定三连：`syncRoof` + `syncMailbox` + `trip.sync`
- `onTick` 每 15 秒轮询信箱——最大消耗点：挂屋顶 10 分钟 ≈ 40 次调用
- `inventory-picker` 每次打开/切 tab 都 `fetchOwned`；`memo` 每次 `onShow` 都拉
- 每读一封信 1 次 `markSeen`（逐封）

**流量侧**：
- BGM 三首 ~7MB；`preloadBgm` 不检查 `musicEnabled`，音乐关闭也白下
- 房间小猫 4 张动图 webp 直接走 CDN，跨会话重复下载

## 第三批：影响前端的后端 ⏳ 进行中

> 第三批 = **影响前端的后端改动**：云端新增聚合/契约接口，需要前端发版切换后才能生效。
> 与第一批（纯前端）、第二批（老前端无感的后端）相对。
> 策略：**新增不删旧**——旧 action 全部保留，老前端无感；前端切换与后端发布不强制同窗口（后端先行无害）。

### 后端部分 ✅ 已完成（2026-10-13，全部 mock + 部署 + 回读线上确认）

1. **showcase.batchGet**：一次返回 展示柜+商店+扭蛋图鉴 三段（结构同 shop.list / gacha.catalog）；
   单段失败置 null 不影响其他段。mock 16/16。
2. **roof.syncAll**：一次返回 stars + trip + mailbox 三段（结构同 roof.sync / trip.sync / postcard.mailbox）；
   行程推进（advanceTrip）整次只执行一遍，行程段与信箱段共享结果，含 returned 孤儿自愈。mock 14/14。
3. **postcard.markSeen 免 tripId 批量**：`{instanceIds:[]}` 不带 tripId 时跨全部邮件行程落位；
   老前端 `{tripId, instanceId}` 单条路径完全保留。mock 10/10。

### 验证轮（2026-10-13 补）— 场景测试 30/30 + 发现并修复 2 个真实 bug

- **syncAll 数据延迟修复**：行程段"孤儿自愈"后，信箱段的 `traveling/hasDelivered` 改用自愈后的
  currentTripId 计算（原先读自愈前的 user 快照，鸽子状态会延迟一拍到下次 sync）
- **syncAll 语义对齐**：currentTripId 指向 at_home 历史行程时，trip 段原样返回 at_home 文档
  （与旧 trip.sync 对齐），不再误清 currentTripId
- **存量 bug 修复（trip 函数）**：`syncTrip` 孤儿自愈的 `reduce(..., null)` 首迭代对 null 取属性抛
  TypeError，被 try/catch 吞掉导致自愈从未生效——生产环境"回家播报不可达"的潜在元凶。已修并 mock 验证
- 场景覆盖：在途未投递/在途已投递/归来未确认/孤儿自愈/at_home 历史信留存/at_home 瞬态/无行程/旧 action 回归/未登录
