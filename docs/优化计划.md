## 调用次数优化 · 第四轮（2026-10-15 完成，前端未发布）

### 1. 旅行中轮询降频（纯前端）

- roof onTick 的"回归检查 + 信箱拉取"双 60s 门合并为单一 **5min `roof.syncAll`** 轮询
  （一次 callFunction 拿回 trip+mailbox 两段，`resolveTripSyncView(prefetched)` 预取路径不再二次发起；
  `applyTripView` 从 syncTripState 抽出共用）。回家精确唤醒仍由 `scheduleReturnWatch` 负责，
  5min 只兜"闹钟失效"，代价是回家横幅/途中信最坏晚 5 分钟。
- home 回归兜底轮询 60s → 5min。
- roof/home 的 onHide 均停表，隐藏页面不烧调用（核实无误，未改）。
- `services/trip.ts` 抽 `applyTripToProfile`（syncTrip 与预取路径共用 profile 落地）。

### 2. login 会话缓存（省每次冷启动 2 次 login 调用）

- `services/auth.ts`：profile 缓存 storage（key `login-session-cache`），**TTL 12h**，命中即
  `setProfile` 返回，零请求。不缓存：教程未完成（login 承担教程残留行程自愈）/ GM（后台改动即时生效）。
- **鉴权错误（UNAUTHORIZED/NOT_FOUND）清缓存强制重登一次**；`ensureSession(force)` 可绕过。
- **inflight 合并**：app onLaunch 与 loading bootstrap 同帧并发共享同一请求（连首登都省掉重复 1 次）。
- `CACHE_VERSION` 常量：login 返回结构变更时 +1 作废旧缓存。
- 换号隔离：小程序 storage 以微信账号维度隔离，读不到旧账号缓存。
- 已知边界：GM 把已完成教程用户重置回教程态时，缓存用户最长 12h 内不重启教程（管理员的自测号
  均为 gm=true 不缓存，不受影响）；多端 profile 展示字段最长 12h 不同步（无经济损失）。

### 3. 后端：lastLoginAt 改由 roof.syncAll 承接（已部署+回读）

- `roof.syncAll` 内顺带刷新 `lastLoginAt`：距上次写入 >1h 才 update，写失败不阻断 sync。
  原因：login 缓存命中时冷启动不再调 login，登录时间戳靠这条兜底，运营统计精度不变。
- mock 4/4（2h 前刷/30min 不刷/缺失刷/写错不阻断），已部署并 `fn code download` 回读确认。

### 4. 信箱已读攒批（前端消费第三批 markSeen 批量接口）

- `mail-box-modal`：读信只记 `_pendingSeen`（本地立即变已读），三触发点 flush——
  关弹窗（visible observer）/ `detached` / pending≥5；失败保留 pending 下次重试，flush 有重入锁。
- `services/postcard.ts`：新增 `markMailsSeen(instanceIds)`（免 tripId）；旧单条 `markMailSeen` 已删除
  （服务端老 action 保留兼容）。mock 6/6。
- 极端情况：读信后直接杀小程序，未 flush 的信服务端保持未读，下次 sync 重新显示 new（与旧实现同风险）。
